# PWA Setup for RTO Autopilot

This document explains the Progressive Web App (PWA) implementation for RTO Autopilot and how to test it on real devices.

## What Was Added

### 1. Web App Manifest (`app/static/manifest.json`)
- **Purpose**: Tells the browser how the app should behave when installed on a device
- **Features**:
  - App name: "RTO Autopilot"
  - Theme color: `#447090` (matches Tailwind primary-600)
  - Background color: `#f9fafb` (matches gray-50)
  - Icons: 192x192 and 512x512 PNG files
  - Display mode: "standalone" (hides browser UI when installed)
  - Orientation: "portrait" (optimized for phone use)
  - Shortcuts: Quick access to "Check Status" and "New Case" from home screen

### 2. App Icons (`app/static/icon-192.png`, `app/static/icon-512.png`)
- **Purpose**: Displayed on the home screen and in app switcher
- **Design**: Blue square (`#447090`) with white "RA" text
- **Generated by**: `generate_icons.py` script using Pillow library

### 3. Service Worker (`app/static/sw.js`)
- **Purpose**: Caches the app shell for offline functionality
- **Features**:
  - Caches essential assets (icons, Tailwind CDN, HTML pages)
  - Skips caching sensitive routes (login, logout, signup, API routes)
  - Implements "stale-while-revalidate" strategy: serves from cache, updates in background
  - Shows offline page when network is unavailable
  - Automatically cleans up old cache versions

### 4. Offline Page (`app/templates/offline.html`)
- **Purpose**: Friendly message when user is offline
- **Features**:
  - Matches app's Tailwind styling
  - "Try Again" button to reload the page
  - Served by service worker when network fails

### 5. Static File Serving (in `app/main.py`)
- **Purpose**: Makes PWA assets accessible to the browser
- **Changes**:
  - Added `StaticFiles` import
  - Mounted `/static` directory at line 86
  - Added `/offline` route for the offline page

### 6. HTML Template Updates
- **base.html** (and signup.html which doesn't extend base):
  - Added manifest link: `<link rel="manifest" href="/static/manifest.json">`
  - Added theme color meta tag: `<meta name="theme-color" content="#447090">`
  - Added icon links for various sizes and Apple touch icon
  - Added service worker registration script

### 7. Mobile UI Optimizations
All templates were updated for one-handed phone use:
- **Touch targets**: Minimum 48px height for buttons and links (WCAG 2.1 AA compliance)
- **Button sizing**: Increased from `py-2` to `py-3` for better tapability
- **Text sizing**: Increased from `text-sm` to `text-base` on buttons for readability
- **Layout**: Added `overflow-x-hidden` to prevent horizontal scrolling
- **Spacing**: Adjusted margins and padding for better mobile spacing
- **Flexbox**: Used `gap` instead of negative margins for better responsive behavior

## How to Test on Real Devices

### Prerequisites
1. Your app must be running on a publicly accessible URL (not localhost)
2. HTTPS is **required** for PWA features to work
3. On development, you can use ngrok or similar tunnel to expose localhost with HTTPS

### Testing on Android (Chrome)

#### Option 1: Lighthouse Audit (Desktop)
1. Open Chrome DevTools (F12)
2. Go to the "Lighthouse" tab
3. Select "Progressive Web App" category
4. Click "Analyze page load"
5. Review the PWA checklist (manifest, service worker, HTTPS, etc.)

#### Option 2: Real Device Install
1. Open Chrome on your Android phone
2. Navigate to your app's URL (must be HTTPS)
3. Wait for the page to fully load
4. Look for the "Add to Home Screen" prompt (may take a few seconds)
5. If prompt doesn't appear:
   - Tap the three-dot menu (⋮) in Chrome
   - Select "Add to Home Screen" or "Install App"
6. Confirm installation
7. The app icon should appear on your home screen
8. Tap the icon to launch - it should open in standalone mode (no browser UI)
9. Test offline: Turn off WiFi/data, open the app - should show offline page

#### Option 3: Chrome DevTools Remote Debugging
1. Enable USB debugging on your Android phone
2. Connect phone to computer via USB
3. On phone, open Chrome and navigate to `chrome://inspect`
4. On computer, open Chrome and go to `chrome://inspect`
5. Find your device under "Remote Target"
6. Click "inspect" to open DevTools for the mobile page
7. Check "Application" tab for Service Worker status and Cache Storage

### Testing on iPhone (Safari)

#### Option 1: Real Device Install
1. Open Safari on your iPhone
2. Navigate to your app's URL (must be HTTPS)
3. Tap the "Share" button (square with arrow pointing up)
4. Scroll down and tap "Add to Home Screen"
5. You can edit the name if desired
6. Tap "Add"
7. The app icon should appear on your home screen
8. Tap the icon to launch - it should open in fullscreen mode
9. Test offline: Turn off WiFi/data, open the app - should show offline page

#### Option 2: Safari Web Inspector
1. On iPhone, enable Web Inspector: Settings > Safari > Advanced > Web Inspector
2. Connect iPhone to Mac via USB
3. On Mac, open Safari and go to Develop > [Your iPhone]
4. Select your webpage to inspect
5. Check the "Application" tab for manifest and service worker info

### Testing Service Worker

#### Chrome DevTools
1. Open DevTools (F12)
2. Go to "Application" tab
3. Click "Service Workers" in left sidebar
4. Check if service worker is registered and active
5. Update on reload: Toggle to force refresh
6. Unregister: Click to unregister if needed

#### Offline Testing
1. Open DevTools > Network tab
2. Check "Offline" in the throttling dropdown
3. Reload the page
4. Should see offline page
5. Go back online and reload to confirm normal operation

### Testing Manifest

#### Chrome DevTools
1. Open DevTools (F12)
2. Go to "Application" tab
3. Click "Manifest" in left sidebar
4. Verify all fields are correctly populated
5. Click "Add to home screen" button to simulate install

#### Safari
Safari doesn't show manifest in DevTools, but you can:
1. Navigate to `/static/manifest.json` directly
2. Verify JSON is valid and loads correctly

## Common Issues

### "Add to Home Screen" doesn't appear
- **Cause**: Service worker not active, or manifest has errors
- **Fix**: Check DevTools Application tab for service worker status
- **Fix**: Verify manifest.json is valid JSON and accessible
- **Fix**: Ensure HTTPS is working (required for PWA)

### Service worker not registering
- **Cause**: Path mismatch or not served correctly
- **Fix**: Check that `/static/sw.js` is accessible
- **Fix**: Check browser console for registration errors

### Icons not showing
- **Cause**: Icon files not accessible or wrong path
- **Fix**: Verify `/static/icon-192.png` and `/static/icon-512.png` load in browser
- **Fix**: Check FastAPI static file mounting is working

### App opens in browser instead of standalone
- **Cause**: Manifest display mode or other PWA criteria not met
- **Fix**: Run Lighthouse PWA audit to see missing criteria
- **Fix**: Ensure service worker is active

### Offline page not showing
- **Cause**: Service worker not caching correctly
- **Fix**: Check Cache Storage in DevTools Application tab
- **Fix**: Verify service worker is intercepting fetch requests

## Deployment Notes

When deploying to production:
1. Ensure your domain has HTTPS enabled (Let's Encrypt or similar)
2. Update manifest.json `start_url` if your app doesn't live at root
3. Consider adding a build step to generate optimized icon sizes
4. Monitor service worker cache size and implement cache cleanup if needed
5. Test on real devices before release
